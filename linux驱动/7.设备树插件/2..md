### 二、 实战拆解：用 `configfs` 加载/卸载设备树插件

我们来看看，当你在终端里敲下那几行命令时，这套魔法是如何完美运转的：

#### 步骤 1：开门营业

Bash

```
mount -t configfs none /sys/kernel/config
```

这句话的意思是：“启动 `configfs` 魔法系统，把它挂载到 `/sys/kernel/config` 目录下。”

#### 步骤 2：下达订单（建文件夹）

Bash

```
mkdir /sys/kernel/config/device-tree/overlays/my_sensor
```

- **用户视角**：我只是建了个叫 `my_sensor` 的空文件夹。
    
- **内核视角**：内核立刻收到通知，在底层创建了一个 `dt_overlay` 的核心结构体。不仅如此，内核还非常贴心地在这个新文件夹里，自动生成了几个属性文件（比如 `dtbo`、`status`、`path`），等着你往里面填数据。
    

#### 步骤 3：注入灵魂（灌入 .dtbo 二进制数据）

Bash

```
cat sensor.dtbo > /sys/kernel/config/device-tree/overlays/my_sensor/dtbo
```

- **用户视角**：我把编译好的插件文件内容，塞进了那个 `dtbo` 属性文件里。
    
- **内核视角**：内核读取到这股数据流，立刻开始解析里面的 `__overlay__` 和 `target`，然后把这个传感器节点死死地“焊”进系统当前正在运行的设备树族谱里。如果匹配到了驱动，驱动的 `probe` 函数瞬间执行，硬件开始工作！
    

#### 步骤 4：拔掉设备（删文件夹）

Bash

```
rmdir /sys/kernel/config/device-tree/overlays/my_sensor
```

- **用户视角**：我把这个文件夹删了。
    
- **内核视角**：内核收到销毁指令。它会立刻去设备树族谱里，把刚才加进去的那个传感器节点**连根拔起**。如果驱动正在运行，内核会强制调用驱动的 **`remove`** 函数，停止硬件工作，最后释放所有内存。

### 三、 工业界超高频应用：USB Gadget (复合设备)

除了设备树插件，`configfs` 在现代 Linux 还有一个极其重要、也是你以后做板子绝对会用到的场景：**配置 USB 从设备 (USB Gadget)**。

假设你的 RK3568 板子有一个 Type-C 接口连着电脑。你想让这根线干嘛？

- 以前（老版本内核）：你只能在编译内核时写死，要么当 U盘，要么当虚拟网卡，不能改。
    
- 现在（有了 `configfs`）：你可以通过在 `/sys/kernel/config/usb_gadget/` 下面疯狂建文件夹（`mkdir`），把你的板子**同时变成**：一个 U盘 + 一个虚拟串口 + 一个鼠标！
    

你甚至可以通过写个简单的 Shell 脚本，一按板子上的按键，立刻 `rmdir` 删掉鼠标功能，`mkdir` 增加网卡功能。**这一切全部在用户态动态完成，完全不需要改 C 代码！**
