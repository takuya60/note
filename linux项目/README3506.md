# 基于 RK3506 的工业级嵌入式 Linux 终端——从异构协同到底层 OTA 的全栈实践

  

> 核心架构：Linux 6.1 主线内核 + 256MB NAND Flash (UBI) + AMP (Cortex-A7 + M0 异构协同)

  

---

  

## 一、 项目概述

  

### 1.1 产品定义

  

一台**具备资源极致约束与工业级可靠性的嵌入式 Linux 终端**。

与传统的通用 SoC 项目不同，本项目部署在仅有 1GB 内存和 256MB NAND Flash 的 RK3506 芯片上，倒逼开发者深入 Linux 存储栈底部（MTD/UBI）实现双备份网络 OTA（永不变砖），并首次在项目中引入前沿的 **AMP（不对称多处理）架构**，利用芯片内置的 Cortex-M0 核心进行硬实时传感器采集，彻底释放 Linux 端的性能。

  

### 1.2 核心亮点与简历关键词

  

| 亮点 | 简历关键词 / 涉及内核子系统 |

|------|-----------|

| **NAND MTD 优化与 A/B Volume OTA** | U-Boot 改造、MTD/UBI 框架、UBIFS、坏块管理、固件原子切换与自动回滚 |

| **AMP 异构多核通信（王炸亮点）** | FreeRTOS 移植、Mailbox / RPMSG 机制、共享内存 IPC、软硬实时解耦 |

| **UART Line Discipline 内核模块** | TTY 子系统、内核态协议解析、状态机设计 |

| **I2C IIO 集成与外设驱动** | I2C 总线、IIO 框架、PWM 子系统、Linux 6.1 设备树 (DTS) |

| **Watchdog 驱动与防砖恢复网** | 看门狗子系统、硬件宕机自动恢复、U-Boot boot_count 机制 |

| **Buildroot 系统极限深度定制** | 交叉编译、内核极限裁剪、根文件系统精简（目标全量包 < 120MB） |

  

### 1.3 极限界限与目标

  

| 指标 | 基线（RK3568 原厂参考） | RK3506 极限挑战目标 |

## 三、 核心模块详细设计

  

### 3.1 模块一：基于 NAND 的 UBI A/B 分区 OTA 系统（⭐ 核心壁垒）

  

在 eMMC 上做 OTA 只是简单的文件拷贝（dd）；在 NAND Flash 上做 OTA 则是考验对底层存储原理的真正理解（因为 NAND 不能直接复写，必须擦除块，且包含坏块）。

  

#### UBI 存储架构设计

我们建立三层架构，隔离硬件坏块带来的灾难：

1. **MTD 层 `/dev/mtd2`**：划出一块 200MB 的物理分区用于系统存放。

2. **UBI 层 `/dev/ubi0`**：在 MTD2 上建立抽象层，负责透明替换坏块，并在全盘做磨损均衡，延长 Flash 寿命。

3. **Volume 卷层**：在 `ubi0` 内切分出两个动态逻辑卷（Volume）：

   - `rootfs_A` (活跃)

   - `rootfs_B` (备用/OTA用)

  

#### OTA 降维打击流程（杜绝变砖）

1. 用户态的 `ota_daemon` 每分钟自动向局域网 HTTP 服务器核对最新版本 `version.json`。

2. 发现新版后，后台静默下载固件 `update.img` 到内存虚拟盘（tmpfs）。

3. 校验 SHA256 无误后，调用专门的 UBI 接口命令（`ubiupdatevol /dev/ubi0_1 update.img`），原子性地擦除并复写备用卷 **rootfs_B**。

4. **修改 U-Boot 配置字**（boot_slot = B, boot_count = 0），并发起系统软重启。

5. **U-Boot 启动与回滚看门狗**：

   - U-Boot 脚本根据 boot_slot 从对应的 B 卷挂载 UBIFS，启动内核。

   - `boot_count` 加一。如果在启动中途内核崩溃（死机），无人喂狗的硬件 **Watchdog** 驱动强制物理复位电路。

   - U-Boot 会检测到 `boot_count > 3`，判定升级失败，执行 **自动回退逻辑**（boot_slot = A），并把 B 卷标记为失效。这确保了哪怕在升级中途拔掉电源，系统也绝不会瘫痪。

  

---

  

### 3.2 模块二：AMP 异构多核通信机制（⭐ 最新杀手锏）

  

传统 Linux 读传感器（如 I2C），受制于 Linux 分时调度和非实时内核的设计，会有几毫秒甚至几十毫秒的中断延迟抖动（Jitter）。

RK3506 内部自带了一颗 **Cortex-M0 微控制器**。我们把对时间高度敏感的传感器轮询（比如 BME280 通过 I2C 毫秒级采样）全权扔给这颗 M0 办理（跑 FreeRTOS）。

  

#### 工作流：

1. **M0 实时采集**：M0 内部通过寄存器极其精准地每 5 毫秒完成一次 I2C 采样，不受任何 Linux CPU 占用率的干扰。

2. **共享内存同步**：M0 将整理好的数据推入芯片内部一段预先商量好的 SRAM（共享内存环形缓冲区）。

3. **Mailbox 邮箱触发**：M0 向 A7（Linux 侧）发送一个硬件级的 Mailbox 核间中断信号。

4. **Linux 极速读取**：Linux 内核接收到 Mailbox 中断向量，从共享内存里将干净、规律的数据一次性取走。

  

简历话术：“**在 RK3506 上应用 AMP 架构，利用内建 Cortex-M0 处理器卸载 Linux 对硬实时传感器的采集任务。通过 Mailbox 中断与共享内存框架实现 A7 与 M0 间的零级缓冲通信，彻底根除在高负载场景下的采样抖动与丢帧。**”

### 3.3 模块三：手写内核驱动群（基于 Linux 6.1）

  

由于 Linux 6.1 是更新的主线级别 LTS 内核，它的 API（如 GPIO 子系统从 旧的 `gpio_xxx` 全面切向新的 `gpiod_xxx` 模型）对代码规范性提出了更高要求。

  

1. **UART Line Discipline（自定义行规程模块）**：

   - 编写挂载在 TTY 子系统的内核模块。拦截来自 STM32 发送的裸数据流。

   - 在内核态实现一套极简帧协议解析引擎（包头 0xAA 55 + CRC16 校验），把解析出的一条条干净命令通过 Netlink 或者字符节点安全地上报给应用程序。免去了用户态频繁系统调用（CPU 用户/内核态切换）读取零碎串口字符的开销。

2. **Watchdog（看门狗子系统驱动）**：

   - 与阶段 3.1 的 OTA 回滚机制深度绑定。如果守护进程挂死，无法向 `/dev/watchdog` 发送 ioctl 喂狗，立刻执行系统级硬复位。

3. **PROC/SYSFS 可观测性节点**：

   - 为手写驱动注入自定义的 `/sys/class/` 属性节点，通过 `cat /sys/...../status` 可以直接查看底层丢包率和中断触发次数，具备大厂运维可观测基因。

  

---

  

### 3.4 模块四：Buildroot 极限界限切割（系统瘦身）

  

我们面对的是物理极限 256MB，而原厂做出来的测试包动辄 1.4 GB。为了能挤下 A/B 两个分区，我们的单区根文件系统必须控制在 **60MB 以下**！

  

- **内核裁剪菜单 (Menuconfig)**：精准关闭多媒体音视频解码子系统 (V4L2, ALSA)，关闭过时的文件系统 (Btrfs, XFS)，仅特供 UBIFS 支持。

- **Buildroot 重组**：剔除所有庞大的调试分析工具、Gstreamer 视频管线。从 glibc 换血优化（如视情况考量使用 musl-libc 进一步削减基础 C 库体积）。使用精简版 Busybox 替换标准 Coreutils 工具集。

  

---

  

### 3.5 模块五：Qt EGLFS 状态监控看板

  

无需复杂笨重的 X11 桌面服务器，直接交叉编译基于 EGLFS 的裸机 Qt 环境。

利用 QML 开发一个响应式看板：

- 左侧：实时大字显示 M0 不断传来的 I2C 传感器数据。

- 右侧上：系统盘（NAND UBI 卷）实时剩余健康寿命展示。

- 右侧下：后台 OTA 状态动画监控进程（正在下载版本包... -> 正在刷新 B 卷... -> 准备就绪自动重启待命）。
