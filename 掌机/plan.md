# RK3506G 综合实战项目：双模式智能桌搭与 MD 复古掌机 (修订版 V2.0)

## 一、 项目总体架构设计 (单进程多态架构)

本项目旨在基于资源受限的瑞芯微 RK3506G 芯片（128MB RAM + 256MB ROM），打造一个具备极简 Linux 系统的 USB 复合外设与复古游戏终端。

为应对 128MB 内存的严苛限制，系统抛弃传统的“多进程+桌面环境”方案，采用**“单进程异步 I/O + 动态库挂载”**的极限优化架构：

1. **桌搭模式 (默认态)**：
    
    - 设备通过 USB 连接 PC，利用 **ConfigFS** 虚拟为复合设备：串口 (`/dev/ttyGS0`) + 多媒体键盘 (`HID`)。
        
    - PC 端后台 Python 脚本通过串口下发 JSON 格式的硬件状态数据。
        
    - 设备端主程序基于 `epoll` 监听底层文件描述符。使用 **LVGL** 配合 **tinyDRM** 驱动在 320x240 屏幕上渲染仪表盘。
        
    - 旋转 EC11 旋钮，主程序通过写入 HID 节点直接控制 PC 音量。
        
2. **掌机模式 (动态切换态)**：
    
    - 按下物理切换键，主程序触发中断逻辑，隐藏 LVGL UI 渲染层。
        
    - 主程序通过 `dlopen()` 动态加载世嘉 MD 模拟器核心 (**Libretro PicoDrive .so 库**)。
        
    - 模拟器输出的 320x224 画面直接通过主程序写入 `/dev/fb0`（或 DRM 节点），实现近乎满屏的无缝切换。主程序的 `epoll` 循环继续接管所有按键输入并传递给模拟器。
        

## 二、 硬件需求清单 (BOM) 更新

- **核心板**：RK3506G 开发板 (128MB RAM / 256MB 存储，必须引出 USB OTG、SPI、I2S、I2C)。
    
- **显示与触控**：SPI TFT LCD 屏幕 (分辨率 320x240，ST7789/ILI9341) + XPT2046 触摸屏。
    
- **输入设备 (由于 MD 掌机需要较多按键，调整方案)**：
    
    - EC11 旋转编码器 (音量控制与 UI 交互)。
        
    - 模式切换独立物理按键。
        
    - **新增**：I2C 接口的 GPIO 扩展芯片（如 TCA8418 或 PCF8574），用于扩展 MD 所需的十字键 + A/B/C/X/Y/Z 等 10+ 个按键，节省 SOC 宝贵的原生 GPIO。
        
- **音频输出**：I2S DAC 模块 (如 MAX98357) 连接小喇叭。
    

## 三、 分阶段详细实施计划与验收标准

根据工程开发“先底层后上层，先通信后业务”的原则，我们将优先打通 USB 链路。

### 阶段一：极限瘦身 —— 构建专用的底层 Linux 环境

_目标：榨干 128MB 内存的每一滴性能。_

- **具体任务**：
    
    1. 使用 Buildroot 构建交叉编译环境。
        
    2. **核心优化**：将 C 运行库从臃肿的 `glibc` 切换为轻量级的 `musl libc`。
        
    3. **核心优化**：将 init 系统切换为最基础的 `BusyBox init`，砍掉所有无用的常驻后台进程（syslog, networkd 等）。
        
    4. 编译生成精简的 `zImage` 和 `rootfs`。
        
- **验收标准**：系统启动后，在串口终端输入 `free -m`，可用内存（Available）必须大于 80MB。
    

### 阶段二：打通大动脉 —— USB 复合设备 (ConfigFS) 开发 

_目标：让开发板能和 PC 正常对话并充当控制器。_

- **具体任务**：
    
    1. 配置内核设备树 (`.dts`)，将 USB 接口设为 `peripheral/otg` 模式。
        
    2. 在内核 `menuconfig` 中开启 USB Gadget ConfigFS、HID Function 和 CDC ACM Function。
        
    3. 编写包含“音量加/减/静音”功能的 **HID Consumer Control 报告描述符**（十六进制数组）。
        
    4. 编写 `/etc/init.d/` 开机挂载脚本，利用 ConfigFS 将 HID 和 ACM 组合并激活。
        
- **验收标准**：开发板插入 PC，Windows 设备管理器准确识别出“USB 串行设备”和“HID 兼容的符合测试标准的设备”。
    

### 阶段三：视觉与交互底层 —— 显示与输入驱动适配

_目标：为上层 UI 提供高效的渲染通道和稳定的输入事件。_

- **具体任务**：
    
    1. **核心优化**：在设备树中开启 SPI 控制器的 DMA 支持（`rockchip,spi-dma`），极度降低 CPU 搬运图像的负载。
        
    2. 在内核中配置 `tinyDRM` 驱动（取代原计划的 FBTFT），实现更高效的局部刷新机制。
        
    3. 编写设备树节点，适配 I2C GPIO 扩展芯片，并通过 Linux `input` 子系统将所有按键和 EC11 注册为标准的 `/dev/input/eventX` 节点。
        
- **验收标准**：通过 `evtest` 测试所有外设能精准上报键值；向 DRM 或 fb0 节点写入随机数据，屏幕能迅速刷新且不撕裂。
    

### 阶段四：中枢神经 —— 基于 epoll 的主控程序与桌搭 UI

_目标：实现高效、无锁的单线程核心业务逻辑。_

- **具体任务**：
    
    1. PC 端使用 Python (`psutil` + `pyserial`) 定时下发 JSON 监控数据。
        
    2. 设备端 C 语言主程序：初始化 `epoll`，将串口 FD 和输入事件 FD 纳入监听。
        
    3. 主循环：`epoll_wait` 非阻塞等待事件。一旦串口有数据则解析 JSON；一旦旋钮转动则向 USB HID 节点写入指令。
        
    4. 在空闲时间片调用 LVGL 的 `lv_task_handler()`，根据解析到的 JSON 数据刷新极客风仪表盘。
        
- **验收标准**：转动设备旋钮，PC 侧音量实时增减；PC CPU 负载变化时，设备端 LVGL 仪表指针平滑跟随，全程系统 CPU 占用率低于 15%。
    

### 阶段五：灵魂切换 —— Libretro MD 掌机无缝融合

_目标：在同一进程内优雅地完成工作态与娱乐态的切换。_

- **具体任务**：
    
    1. 在 Buildroot 交叉编译环境中，将 `PicoDrive` 编译为 `picodrive_libretro.so` 动态链接库。
        
    2. 在主控程序中实现 Libretro 的 Frontend 胶水层接口（实现按键状态映射、音频 I2S 缓冲推流、视频帧 DRM 渲染）。
        
    3. 完善模式切换逻辑：按键触发 -> 挂起 LVGL -> `dlopen` 加载库 -> 进入游戏循环；再次触发 -> 卸载库 -> 恢复 LVGL。
        
- **验收标准**：模式切换在 1 秒内完成，无黑屏撕裂；《刺猬索尼克》等游戏能满帧（60FPS）运行，声音无爆音。
