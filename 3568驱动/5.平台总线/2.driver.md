在实际编写中，注册一个 `platform_driver` 主要分为四个关键步骤。这部分代码也是你以后在 RK3568 或任何平台上写驱动时，改动最频繁、最体现核心业务逻辑的地方。

---

### 第一步：写下“择偶标准”（匹配列表）

女嘉宾来相亲，必须先告诉红娘她想找谁。在平台总线中，这叫做**匹配表（Match Table）**。

最传统的匹配方式是**比对名字**。我们需要定义一个 `platform_device_id` 数组，写下我们能接受的男嘉宾名字：

C

```
#include <linux/mod_devicetable.h>

// 定义择偶标准：我只接受名字叫 "rk3568-myled" 的设备
static const struct platform_device_id led_id_table[] = {
    { "rk3568-myled", 0 }, // 名字必须和 Device 里的一模一样！
    { },                   // 必须以一个空元素结尾，告诉内核列表结束了
};
// 暴露这个列表给内核
MODULE_DEVICE_TABLE(platform, led_id_table);
```

### 第二步：规划“婚后生活”（编写 `probe` 和 `remove` 函数）

这是整个驱动**最核心**的灵魂所在。

- **`probe`（探测函数 / 领证入住）**：当总线发现男女嘉宾名字匹配成功时，会**立刻主动调用**这个函数！并且把男嘉宾的所有家当（`struct platform_device *pdev`）交到女嘉宾手上。
    
- **`remove`（移除函数 / 离婚清算）**：当设备被拔出，或者驱动被卸载时调用，负责把 `probe` 里申请的资源全部还回去。
    
![[Pasted image 20260221234432.png]]
看看 `probe` 函数里到底干了什么：

```c
#include <linux/platform_device.h>
#include <linux/ioport.h>
#include <asm/io.h>

// 匹配成功后，内核会把男嘉宾 (pdev) 送进来
static int led_probe(struct platform_device *pdev)
{
    struct resource *res;
    void __iomem *vir_base;

    printk("匹配成功！开始交接硬件资源...\n");

    // 1. 【查房产证】：从男嘉宾手里获取第 0 个内存资源（寄存器物理地址）
    res = platform_get_resource(pdev, IORESOURCE_MEM, 0);
    if (!res) {
        printk("男嘉宾是个骗子，没有房产证！\n");
        return -EINVAL;
    }

    // 2. 【拿到钥匙】：将物理地址映射为虚拟地址 (ioremap)
    vir_base = ioremap(res->start, resource_size(res));
    if (!vir_base) {
        printk("地址映射失败！\n");
        return -ENOMEM;
    }

    // 3. 【开始装修】：注册字符设备、创建 /dev/myled 节点、配置 GPIO 为输出
    // ... 这里写你之前学过的那些点灯逻辑 ...

    printk("LED 驱动初始化完毕，可以亮灯了！\n");
    return 0; // 返回 0 表示领证成功，以后就长相厮守了
}

// 离婚时的清理工作
static int led_remove(struct platform_device *pdev)
{
    // 1. 熄灭 LED
    // 2. 取消虚拟地址映射 (iounmap)
    // 3. 注销字符设备、删除节点
    printk("驱动已卸载，资源清理完毕。\n");
    return 0;
}
```

### 第三步：填写“个人简历”（组装 `struct platform_driver`）

现在把前面的“择偶标准”和“婚后规划”打包，填进女嘉宾的正式简历 `struct platform_driver` 中。

```c
static struct platform_driver led_driver = {
    .probe  = led_probe,      // 匹配成功调用的函数
    .remove = led_remove,     // 卸载时调用的函数
    .id_table = led_id_table, // 择偶标准（传统的按名字匹配）
    
    .driver = {
        .name = "rk3568-myled-driver", // 驱动自己的名字（注意：这个名字主要是给人看的，匹配主要靠 id_table）
        .owner = THIS_MODULE,
    },
};
```

### 第四步：正式提交给婚介所（注册）

最后，在模块加载函数中，把这个 Driver 注册到平台总线上。

```c
#include <linux/module.h>

static int __init led_driver_init(void)
{
    // 注册女嘉宾
    return platform_driver_register(&led_driver);
}

static void __exit led_driver_exit(void)
{
    // 注销女嘉宾
    platform_driver_unregister(&led_driver);
}

module_init(led_driver_init);
module_exit(led_driver_exit);
MODULE_LICENSE("GPL");
```

### 💡 一个震撼内核圈的“偷懒绝招”

如果你认真看了第四步的代码，你会发现：注册和注销 Driver 的代码非常死板，永远都是那几行。

Linux 内核的大佬们为了减少这种“样板代码（Boilerplate）”，发明了一个极其好用的宏。**你可以把第四步的整个 `init`、`exit` 函数，以及 `module_init`、`module_exit`，全部删掉！**

只需要在代码最后写下这神奇的一行：

C

```
module_platform_driver(led_driver);
```

**这一行代码，等价于前面几十行的模块注册和注销代码！** 在现代 Linux 驱动开发中，几乎所有的工程师都会使用 `module_platform_driver()` 这个宏来注册平台驱动。用了它，你的代码瞬间就有了资深内核开发者的味道。

### 总结整个流程闭环：

1. 你先 `insmod device.ko`，总线上多了一个叫 `rk3568-myled` 的设备。
    
2. 你再 `insmod driver.ko`。
    
3. 总线立刻拿着 Driver 的 `id_table` 去设备列表里找，发现名字对上了！
    
4. 总线把 `device` 的指针塞进 `driver` 的 `probe` 函数里。
    
5. `probe` 开始执行，通过 `platform_get_resource` 成功拿到物理地址，映射虚拟地址，点亮 LED。
