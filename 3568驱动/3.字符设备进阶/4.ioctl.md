应用层在调用ioctl的时候
```c
ioctl(fd,cmd,参数 (可变))
```
### cmd的构成
一共由32位构成
前八位是设备类型 第二个八位是序列号，代表这个设备的第几个命令
第三部分代表方向 占2bit
- 10 01 11 00   10是只读 01是只写  11是读写 00是无数据
第四部分代表数据尺寸 传递的是设备类型

## cmd的合成与分解
### 合成
![[Pasted image 20260211231421.png]]
这个通常在头文件里定义 这样 应用层和驱动层就都知道是什么，比如
```c
#ifndef _MY_IOCTL_H
#define _MY_IOCTL_H

#include <linux/ioctl.h> // 必须包含这个

// 1. 随便找个不冲突的字符 代表设备类型
#define MY_MAGIC 'K'

// 2. 定义命令
// 命令0：只是打印一句话 (无参数)
#define CMD_HELLO       _IO(MY_MAGIC, 0)

// 命令1：设置值 (写 int)
#define CMD_SET_VAL     _IOW(MY_MAGIC, 1, int)

// 命令2：获取值 (读 int)
#define CMD_GET_VAL     _IOR(MY_MAGIC, 2, int)

#endif
```
应用层在包含了上面的头文件之后
```c
ioctl(fd,CMD_SET_VAL,666);
```
驱动层：在对应的ioctl处理函数里面，对cmd进行判断
这个ioctl函数，也是在file oprations里面的
```c
long my_ioctl(struct file *file, unsigned int cmd, unsigned long arg)
{
    // 1. 安全检查：是不是发给我的？
    if (_IOC_TYPE(cmd) != MY_MAGIC)
        return -EINVAL;

    // 2. 处理命令
    switch(cmd) {
        case CMD_HELLO:
            printk("Hello cmd received!\n");
            break;

        case CMD_SET_VAL:
            // 注意：虽然定义了 _IOW，但内核不会自动帮你拷数据
            // arg 只是个地址，你还是要自己 copy_from_user
            // 只是 _IOW 宏保证了这个 cmd 数字是独一无二的
            int val;
            copy_from_user(&val, (int __user *)arg, sizeof(int));
            printk("Set val: %d\n", val);
            break;
            
        case CMD_GET_VAL:
            int data = 100;
            copy_to_user((int __user *)arg, &data, sizeof(int));
            break;
    }
    return 0;
}
```
