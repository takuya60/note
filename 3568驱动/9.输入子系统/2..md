在上一节的代码里，我们用到了这两行：

C

```
__set_bit(EV_KEY, my_button_dev->evbit);
__set_bit(KEY_ENTER, my_button_dev->keybit);
```

要把 `evbit` 和 `keybit` 彻底搞懂，我们只需记住一个核心比喻：它们就是你的硬件交给内核的**“技能点鉴定表（能力清单）”**。

这其实是一个**“大类”**和**“小类”**的包含关系。我们一层层扒开来看：

---

### 1. `evbit` (Event Bit)：大类技能树（我会干哪一行的活？）

`ev` 是 **Event（事件）** 的缩写。`evbit` 里面记录的是这个设备支持的**“事件大类”**。

Linux 内核把世界上所有的输入动作，分成了几个主要的大门派：

- **`EV_KEY`**：按键类（包括键盘按键、鼠标左右键、手柄按钮）。
    
- **`EV_REL`**：相对位移类（比如鼠标向左滑动了多少，向右滑动了多少，它是相对当前位置的）。
    
- **`EV_ABS`**：绝对位移类（比如触摸屏，你点在哪里就是确切的屏幕坐标）。
    
- **`EV_LED`**：LED 提示类（比如键盘上的 CapsLock 大写锁定指示灯）。
    
- **`EV_SND`**：声音提示类（比如蜂鸣器报警）。
    

所以，当你写下 `__set_bit(EV_KEY, my_button_dev->evbit);`，你其实是在向内核大喊：**“长官！我申请点亮【按键类】的技能树！”** ---

### 2. `keybit` (Key Bit)：小类技能分支（我具体会干啥？）

如果你只点亮了 `EV_KEY`（按键类），内核会很懵：“全世界有几千种按键，你到底支持哪一个？”

这时候，**`keybit`** 就登场了。它专门用来补充说明 `EV_KEY` 大类下的**具体小类（Code）**。

在 Linux 的 `<linux/input.h>` 头文件里，定义了极其庞大的按键代码库：

- `KEY_ENTER` (回车键)
    
- `KEY_A`, `KEY_B`, `KEY_C` (字母键)
    
- `KEY_POWER` (电源键)
    
- `BTN_LEFT`, `BTN_RIGHT` (鼠标左键、右键，注意鼠标按键也属于 `EV_KEY` 大类！)
    
- `BTN_TOUCH` (触摸屏按下瞬间的动作，也算按键！)
    

所以，当你写下 `__set_bit(KEY_ENTER, my_button_dev->keybit);`，你是在做详细的述职报告：**“长官，在按键类这个大门派里，我具体只会发【回车键】的信号！”**

_(注：除了 `keybit`，如果你点亮了 `EV_REL`，就会对应有一个叫 `relbit` 的数组；点亮了 `EV_ABS`，就会有一个 `absbit`。规矩都是一样的。)_

---

### 3. 底层黑客视角：为什么名字里带个 `bit`？

很多初学者会疑惑，为什么不用数组或者链表来存这些能力，偏偏要叫 `bit`（位）？

这体现了 Linux 内核对**极致性能和省内存**的变态追求！

在 `struct input_dev` 结构体里，`evbit` 和 `keybit` 的真面目其实是**一个由 `unsigned long` 组成的数组（位图 / Bitmask）**。

假设 `unsigned long` 是 32 位的： 内核把所有的事件代码排成一排。第 0 位代表事件 0，第 1 位代表事件 1...

- 如果第 28 位是 `0`，代表你不支持 `KEY_ENTER`（回车键的宏定义值刚好是 28）。
    
- 如果第 28 位是 `1`，代表你支持 `KEY_ENTER`。
    

**`__set_bit(KEY_ENTER, my_button_dev->keybit);` 这个函数的底层动作，其实就是极其底层的位运算，精确地把数组里的第 28 个二进制位强行拨成了 `1`！**

这种“位图”机制的好处是：内核检查你的设备支不支持某个功能时，只需要做一次超级快的 C 语言 `&`（与运算），速度快到飞起。

---

### 4. 如果你不设置这两个 bit 会怎样？（超级大坑）

假设你忘写了这两行代码，但是在中断处理函数里，你依然强行调用 `input_event(my_input, EV_KEY, KEY_ENTER, 1);` 上报数据，会发生什么？

**答案是：你的数据会像泥牛入海，消失得无影无踪！应用层绝对收不到你的回车键！**

**为什么？因为内核会“过滤（Filter）”你的数据！** 当你的驱动调用 `input_event()` 把数据发给核心层时，核心层的保安会立刻翻开你的 `evbit` 和 `keybit` 简历： 保安：“你想上报回车键？但我看你的简历上根本没写你会发回车键啊！你是个假冒伪劣设备，数据丢弃！”

### 总结

- **`evbit`**：告诉内核“我要报按键”。
    
- **`keybit`**：告诉内核“我要报的按键是回车”。
    
- **它们的作用**：一份用于内核防守过滤的“白名单（位图）”。
    

现在你搞懂了这个“大类和小类”的位图机制，你想不想知道，在写现代的 Linux 输入驱动时，除了这种略显古老的 `__set_bit` 写法，内核有没有提供更优雅、更简单的一行代码初始化 API？
