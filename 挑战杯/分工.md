这个赛题是一个非常落地且具有产品级潜力的多智能体（Multi-Agent）项目。赛题的核心在于避免大模型直接生成内容的“千人一面”和“专业幻觉”，而是通过多智能体协作实现诊断、生成、审核、反馈的完整闭环。


下面为你们规划一个典型的项目工程结构，并按照 4 人小组的规模进行分工建议。

## 一、 项目工程结构规划

建议采用前后端分离的架构，并使用结构化的输出格式（如 JSON Schema / Pydantic）来规范 Agent 之间的通信协议。

Plaintext

```
agent_edu_platform/
├── frontend/                        # 前端展示界面
│   ├── app.py                       # Streamlit 主程序入口
│   ├── components/                  # UI 组件（画像报告、学习路径图、资源展示）
│   └── assets/                      # 静态资源
├── backend/                         # 后端服务接口
│   ├── main.py                      # FastAPI/Flask 服务启动文件
│   ├── api/                         # 路由层（接收前端请求，触发 Agent 流程）
│   └── models/                      # 结构化输出模型（JSON Schema / Pydantic 定义）
├── agents/                          # 核心智能体编排
│   ├── workflow.py                  # LangGraph/CrewAI 等框架的状态机图定义与调度逻辑
│   ├── diagnosis_agent.py           # 学情诊断 Agent：根据测试结果定位知识盲区
│   ├── expert_agent.py              # 领域专家 Agent：从知识库提取知识点和实操规范
│   ├── generator_agent.py           # 资源生成 Agent：生成讲义、实操指南、测试题
│   ├── reviewer_agent.py            # 审核纠偏 Agent：检查专业错误、幻觉及难度匹配度
│   └── feedback_agent.py            # 决策反馈 Agent：根据交互反馈调整学习路径
├── rag_engine/                      # 知识库与检索增强模块
│   ├── document_loaders.py          # 解析专业教材、实操步骤、官方文档
│   ├── vector_store.py              # 向量数据库操作（FAISS / Chroma 等）
│   └── retriever.py                 # 知识检索与切片组装逻辑
├── data/                            # 静态数据与测试集
│   ├── knowledge_base/              # 原始专业领域文档切片
│   ├── learner_profiles.json        # 不同背景的学习者画像及测试结果模拟数据
│   └── knowledge_graph.json         # 核心知识点清单及其依赖关系
├── evaluation/                      # 内容评测模块
│   ├── metrics.py                   # 计算知识点覆盖率、难度匹配度等规则评分
│   └── llm_judge.py                 # LLM-as-Judge 幻觉率及专业谬误率评估脚本
├── .env                             # API Key 及环境变量配置
└── requirements.txt                 # 项目依赖
```

## 二、 团队分工建议（按 4 人团队配置）

为了保证项目既有扎实的底层逻辑，又有直观的可视化效果，建议团队按“业务流”和“技术栈”进行交叉分工。

|**角色岗位**|**核心职责**|**对应模块**|**具体任务拆解**|
|---|---|---|---|
|**PM & 领域知识工程师**|负责“喂给”系统什么数据，决定项目的专业深度。|`data/`<br><br>  <br><br>`rag_engine/`|1. 梳理所选垂直领域的知识点结构，制作小型知识点依赖图。<br><br>  <br><br>2. 整理并清洗高质量的知识库材料，如教材片段和实验步骤。<br><br>  <br><br>3. 设计 3 组以上差异化的学习者画像特征及对应的基础测试题。|
|**Agent 算法工程师**|负责大模型提示词工程与多智能体工作流编排。|`agents/`|1. 利用 LangGraph 或自研状态机完成 4-5 个 Agent 的调度工作流设计。<br><br>  <br><br>2. 撰写并调优诊断、生成、审核等 Agent 的 Prompt，确保其能按角色行事。<br><br>  <br><br>3. 实现审核与交叉验证机制，确保审核 Agent 能将问题反馈给生成 Agent 重写。|
|**后端开发与测试工程师**|负责系统接口、RAG 管道打通与量化评测指标实现。|`backend/`<br><br>  <br><br>`evaluation/`|1. 搭建 FastAPI / Flask 后端，提供分析、生成、反馈的稳定接口。<br><br>  <br><br>2. 结合 LangChain 等实现 RAG 检索流程，确保生成内容有知识库支撑。<br><br>  <br><br>3. 编写自动化评估脚本（LLM-as-Judge 和规则评分），统计幻觉率和核心知识点覆盖率。|
|**前端交互与可视化工程师**|负责最终演示 Demo 的实现，把枯燥的流转过程可视化。|`frontend/`|1. 使用 Streamlit / Gradio 开发交互界面，展示左侧输入、中间流程和右侧结果。<br><br>  <br><br>2. 实现学情报告、知识盲区和难度匹配曲线的数据可视化展示。<br><br>  <br><br>3. 渲染最终生成的讲义、可执行代码实操指南和测试题格式。|

_注：如果团队为 3 人，可将“PM & 领域知识工程师”的工作分摊给前端和后端；如果团队有 5 人，可以专门设立一位 RAG 工程师专攻检索准确性和向量数据库调优。_
