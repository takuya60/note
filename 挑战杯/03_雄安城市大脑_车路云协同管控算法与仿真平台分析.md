# XH-202613 面向雄安新区“城市大脑”的车路云一体化协同管控算法与仿真平台分析

## 1. 赛题理解

这个题要求做一个面向雄安新区“城市大脑”的智能交通仿真与管控系统。核心是用仿真平台构建类似雄安“窄路密网”的交通场景，再设计车路云协同算法，证明它比传统固定信号灯控制更能缓解拥堵。

简单说，就是做一个“虚拟城市交通实验场”：车在里面跑，你的算法实时调整红绿灯或给车辆建议，最后用数据证明效果更好。

## 2. 核心难点

1. **要会搭交通仿真场景**：需要学习 SUMO、路网、车辆流量、信号灯配置。
2. **要有可运行算法**：不能只展示路网，要能动态控制交通。
3. **要有基线对比**：必须和固定配时等传统方法比较。
4. **要有展示效果**：交通仿真、拥堵变化、指标曲线要做得直观。

### 3.1 SUMO

SUMO 是开源交通仿真软件，相当于一个虚拟交通沙盘。你可以定义道路、车道、路口、红绿灯、车辆路线和交通流。这个题最适合用 SUMO，因为它成熟、免费、可控，而且支持 Python 接口。

最终展示画面通常就是：车辆在 SUMO 路网上运行，你的算法动态调整信号灯，指标显示拥堵减少。

### 3.2 NetEdit 与 OSM

NetEdit 是 SUMO 自带的路网编辑器，可以手工画道路、车道、路口和红绿灯。初期建议先用 NetEdit 手工画小场景，快速跑通流程。

OSM 是开源地图数据，可以导入真实道路结构，再转换成 SUMO 路网。如果要贴近雄安真实场景，可以后期尝试 OSM 或公开规划资料。

### 3.3 TraCI

TraCI 是 Python 控制 SUMO 的接口。没有 TraCI，你只能看仿真自己跑；有了 TraCI，你就可以实时读取车流并下发控制指令。

TraCI 可以做：

- 获取车辆位置、速度、等待时间。
- 获取车道排队长度。
- 修改红绿灯相位。
- 改变车辆速度。
- 插入事故、施工等扰动。

这个题的核心算法基本都要通过 TraCI 接入 SUMO。

### 3.4 Python 数据分析工具

Python 用来写仿真控制和算法逻辑。

- NumPy：做数值计算。
- Pandas：整理实验结果。
- NetworkX：把路网当成图，分析路口关系和路径。
- Matplotlib / ECharts：画指标变化图。

你们需要用这些工具计算平均等待时间、排队长度、通行量等指标。

### 3.5 交通控制算法

一开始不建议直接做强化学习。更稳妥的算法路线是：

1. 固定配时：传统红绿灯按固定周期变化。
2. 感应式控制：哪个方向排队多，就给哪个方向更多绿灯。
3. Max-Pressure：根据上下游车流压力选择放行方向。
4. 邻接路口协同：避免一个路口放行后把下游堵死。
5. 短时流量预测：提前判断下一阶段哪个方向会拥堵。

这样既可解释，又容易做出稳定提升。

### 3.6 可视化和展示

SUMO 自带 GUI 可以展示车流，但最好再做一个自己的指标面板，展示：

- 当前仿真时间。
- 各路口排队长度。
- 平均等待时间。
- 当前信号灯状态。
- 固定配时和协同控制对比。
- 扰动事件发生位置。

如果前端能力一般，可以用 Streamlit；如果前端较强，可以用 Vue / React + ECharts。

### 3.7 云边端和通信模拟

车路云一体化可以用软件模拟：

- 云端服务：全局监控和策略下发。
- 边缘服务：局部路口控制。
- 车端脚本：模拟车辆上报位置和接收速度建议。

通信可以用 HTTP 或 WebSocket，想更像车联网可以用 MQTT。

## 4. 推荐技术路线

### 阶段一：跑通 SUMO 最小场景

1. 安装 SUMO。
2. 跑通官方示例。
3. 用 NetEdit 画一个 2×2 或 3×3 小路网。
4. 配置车辆路线和红绿灯。
5. 看车辆能否正常运行。

目标：先让车在虚拟路网上跑起来。

### 阶段二：用 Python 控制红绿灯

1. 用 TraCI 启动 SUMO。
2. 每一步读取车辆位置、速度、排队长度。
3. 写一个简单规则：哪个方向排队多，就给哪个方向绿灯。
4. 记录平均等待时间和排队长度。

这一阶段可以做出第一个对比：

- 固定配时。
- 简单感应式控制。

### 阶段三：构建雄安“窄路密网”场景

建议构建一个 20 个路口左右的片区：

- 路口密集。
- 道路较短。
- 部分道路车道少。
- 高峰期车流集中。
- 可模拟施工占道、学校周边、大型活动散场等扰动。

如果没有真实数据，可以基于公开路网结构和“窄路密网”特征构建合成场景。

### 阶段四：实现主算法

不建议一开始就做复杂强化学习。更稳妥的是：

> **Max-Pressure + 邻接路口协同 + 短时流量预测**

基本思路：

```text
读取各方向排队长度
  ↓
计算每个相位的交通压力
  ↓
考虑下游路口是否拥堵
  ↓
选择最需要放行的方向
  ↓
动态调整绿灯时间
```

这个算法比固定配时智能，又比强化学习稳定，适合比赛落地。

### 阶段五：模拟车路云协同

可以用软件模拟三层：

- **云端**：看全局交通状态，发布区域策略。
- **边缘端**：控制几个相邻路口。
- **车端**：模拟车辆上报位置，接收速度建议。

不一定要真实硬件，用不同 Python 模块或进程模拟即可。

### 阶段六：做对比实验和报告

至少比较：

1. 固定配时。
2. 感应式控制。
3. 你的协同控制算法。

核心指标：

| 指标 | 含义 |
|---|---|
| 平均行程时间 | 车辆从起点到终点耗时 |
| 平均等待时间 | 红灯和拥堵等待时间 |
| 平均排队长度 | 路口拥堵程度 |
| 最大排队长度 | 最严重拥堵情况 |
| 通行量 | 单位时间通过车辆数 |
| 平均速度 | 路网运行效率 |
| 能耗 / 排放 | 可由 SUMO 估算 |

## 8. 结论

这是目前最稳的选题之一。它不依赖 GPU，不涉及国产芯片部署，评分清晰，展示效果强。缺点是 AI 味道不如数学智能体和荣耀题，需要通过“智能交通算法 + 云边端协同 + 标准化评估”来补足创新性。
