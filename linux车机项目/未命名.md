# 基于 RK3568 的超轻量实时 Linux 嵌入式系统

> 从 200MB 到 8MB 的极限裁剪，从 30 秒到 5 秒的极速启动
---
## 一、项目概述
### 1.1 项目定位

本项目旨在基于 RK3568 平台，**从零构建一个极致精简的嵌入式 Linux 系统**，并手写多个内核驱动模块。项目核心价值不在于"做了什么应用"，而在于对 Linux 内核的深度理解：**每一个字节为什么存在，每一个被删掉的模块为什么不需要**。
### 1.2 核心目标

| 目标 | 量化指标 |

|------|---------|

| 内核镜像大小 | 从 ~15MB 裁减至 **≤ 5MB** |

| 根文件系统大小 | 从 ~200MB 精简至 **≤ 8MB** |

| 冷启动到应用显示 | 从 ~30s 优化至 **≤ 5s** |

| 手写内核驱动模块 | **3 个**（UART Line Discipline / I2C IIO / PWM） |

| 内核调试接口 | Procfs 统计节点 |

### 1.3 技术栈总览

| 层次 | 技术选型 |

|------|---------|

| 硬件平台 | RK3568（正点原子/迅为） |

| 系统构建 | Buildroot |

| 内核版本 | Linux 5.10（Rockchip BSP） |

| 驱动框架 | TTY Line Discipline / I2C + IIO / PWM Platform Driver |

| 应用展示 | Qt EGLFS + QML（仅做数据展示，非亮点） |

| 从机 | STM32F103C8T6（UART 通信对端） |

## 三、核心模块详细设计

### 3.1 模块一：内核深度裁剪（⭐ 最核心亮点）

这是整个项目的灵魂。目标是对 RK3568 默认内核配置的 **800+ 选项逐项分析**，产出一份完整的《裁剪分析记录》。
#### 3.1.1 裁剪策略

**内核 defconfig 裁剪重点**：

| 分类 | CONFIG 前缀 | 策略 | 说明 |

|------|------------|------|------|

| 文件系统 | `CONFIG_*_FS` | 仅保留 ext4 + tmpfs + proc + sysfs + devtmpfs | 去掉 NTFS/CIFS/NFS/BTRFS/F2FS 等 |

| 网络协议 | `CONFIG_NET_*` | 保留基础 TCP/IP，去掉 IPv6/Netfilter/蓝牙/无线 | 根据是否需要网络决定 |

| GPU 驱动 | `CONFIG_DRM_*` | 仅保留 rockchipdrm | 去掉所有其他 GPU 驱动 |

| USB | `CONFIG_USB_*` | 仅保留 host + storage（调试用） | 去掉 gadget/webcam/printer 等 |

| 输入设备 | `CONFIG_INPUT_*` | 仅保留 evdev + 触摸屏 | 去掉键盘/鼠标/游戏手柄 |

| 音频 | `CONFIG_SND_*` | **全部去掉** | 不需要音频 |

| 多媒体 | `CONFIG_MEDIA_*` | **全部去掉** | 不需要摄像头/视频 |

| 调试 | `CONFIG_DEBUG_*` | 最终版全部关闭 | 开发阶段保留 |

| 安全 | `CONFIG_SECURITY_*` | 去掉 SELinux/AppArmor | 嵌入式场景不需要 |

**initcall 启动优化**：

```bash

# 开启 initcall 调试
# 内核 cmdline 添加：initcall_debug printk.time=1
# 启动后分析耗时
dmesg | grep "initcall" | sort -k4 -n -r | head -30
# 找到耗时长且无用的 initcall，通过裁掉对应 CONFIG 去掉它们
```

**Buildroot 根文件系统精简**：

| 组件 | 选择 | 说明 |

|------|------|------|

| C 库 | musl libc | 比 glibc 小 ~5 倍 |

| 工具集 | BusyBox | 替代 coreutils，一个二进制搞定所有命令 |

| init 系统 | 自定义 shell 脚本 | 不用 systemd/sysvinit |

| 包管理 | 无 | 不需要 |

| 调试工具 | 仅保留 strace（可选） | 最终版去掉 |

#### 3.1.2 交付物

- `configs/rk3568_minimal_defconfig` —— 裁剪后的内核配置文件

- `docs/kernel_trim_analysis.md` —— 裁剪分析记录（逐项说明）

- `docs/boot_time_optimization.md` —— 启动时间优化报告（含 before/after 数据）

### 3.2 模块二：UART Line Discipline 驱动

#### 3.2.1 为什么用 Line Discipline

在 Linux 内核 TTY 子系统中，Line Discipline 是一个**协议解析层**，位于 UART 硬件驱动和用户态之间。普通的串口通信在用户态做帧解析，而 Line Discipline 把解析逻辑**下沉到内核态**，应用层直接 `read()` 就能拿到完整的协议帧。

```

用户态：  应用程序 read(fd, &frame, sizeof(frame))

              │

内核态：  ┌───┴────────────────────────────┐

          │  Line Discipline（你写的模块）   │

          │  - 帧头检测 (0xAA 0x55)         │

          │  - 状态机解析                    │

          │  - CRC16 校验                   │

          │  - 完整帧缓冲                    │

          └───┬────────────────────────────┘

              │

          ┌───┴────────────┐

          │  UART 硬件驱动   │ （内核已有，不用写）

          └────────────────┘

```
#### 3.2.2 帧协议设计

```

┌────────┬──────┬──────┬─────────────────┬────────┐

│ HEAD   │ TYPE │ LEN  │    PAYLOAD      │ CRC16  │

│ 0xAA   │      │      │                 │        │

│ 0x55   │      │      │                 │        │

├────────┼──────┼──────┼─────────────────┼────────┤

│ 2 Byte │ 1 B  │ 1 B  │   0~250 Byte    │ 2 Byte │

└────────┴──────┴──────┴─────────────────┴────────┘

```

**帧类型**：

| 类型 | 值 | 方向 | 说明 |

|------|-----|------|------|

| `DATA_REPORT` | 0x01 | STM32 → RK3568 | 传感器数据上报 |

| `CTRL_CMD` | 0x02 | RK3568 → STM32 | 控制指令 |

| `ACK` | 0x03 | 双向 | 应答确认 |

| `HEARTBEAT` | 0x04 | 双向 | 心跳保活 |

**DATA_REPORT Payload 结构**（STM32 上报）：
  
| 字段 | 大小 | 单位 | 说明 |

|------|------|------|------|

| temperature | int16_t | 0.1℃ | 温度 × 10 |

| humidity | uint16_t | 0.1% | 湿度 × 10 |

| light | uint16_t | lux | 光照强度 |

| reserved | uint16_t | - | 保留 |

#### 3.2.3 状态机设计

```

  收到字节

     │

     ▼

┌──────────┐  0xAA   ┌──────────┐  0x55   ┌──────────┐

│WAIT_HEAD1├────────►│WAIT_HEAD2├────────►│WAIT_TYPE │

└────┬─────┘ 非0xAA  └────┬─────┘ 非0x55  └────┬─────┘

     │◄──────────────────┘ (回到HEAD1)          │

     │                                          ▼

     │                                   ┌──────────┐

     │                                   │WAIT_LEN  │

     │                                   └────┬─────┘

     │                                        ▼

     │                                   ┌──────────┐

     │                                   │WAIT_DATA │

     │                                   │(计数LEN) │

     │                                   └────┬─────┘

     │                                        ▼

     │                                   ┌──────────┐

     │          CRC 正确，帧完成          │WAIT_CRC  │

     │◄──────────────────────────────────┤(2字节)   │

     │          CRC 错误，丢弃            └──────────┘

```

### 3.3 模块三：I2C 传感器 IIO 驱动

#### 3.3.1 目标

手写 BME280 温湿度气压传感器的 I2C client 驱动，注册到内核 IIO（Industrial I/O）子系统。

> 注意：内核主线已有 BME280 驱动，但这里**手写自己的版本**，目的是展示对 I2C 子系统和 IIO 框架的掌握。

#### 3.3.2 驱动注册流程

```

模块加载 (insmod)

    │

    ▼

i2c_add_driver(&my_bme280_driver)

    │

    ▼

内核匹配设备树 compatible = "my,bme280-custom"

    │

    ▼

probe() 回调被调用

    │

    ├── 读取 BME280 芯片 ID (reg 0xD0)，验证是否为 0x60

    ├── 配置采样率、滤波器

    ├── 注册 IIO device（3 个 channel：温度/湿度/气压）

    └── 完成

```
#### 3.3.3 设备树绑定

```dts

&i2c1 {

    status = "okay";

    clock-frequency = <400000>;

  

    bme280@76 {

        compatible = "my,bme280-custom";

        reg = <0x76>;

        /* 可选：采样率等自定义属性 */

        sample-rate-hz = <10>;

    };

};

```
#### 3.3.4 用户态访问方式

```bash

# 读取温度（原始值）
cat /sys/bus/iio/devices/iio:device0/in_temp_raw

# 读取湿度
cat /sys/bus/iio/devices/iio:device0/in_humidityrelative_raw
  

# 读取气压
cat /sys/bus/iio/devices/iio:device0/in_pressure_raw

# 读取缩放因子（用于转换为实际值）
cat /sys/bus/iio/devices/iio:device0/in_temp_scale

```
#### 3.3.5 源文件结构

```

drivers/my_bme280/

├── Kconfig

├── Makefile

├── my_bme280.c          # I2C client 驱动 + IIO 注册

└── my_bme280.h          # 寄存器地址定义

```

### 3.4 模块四：PWM 背光驱动
#### 3.4.1 目标

编写 Platform 驱动控制 LCD 屏幕背光亮度，通过 sysfs 接口暴露给用户态。

#### 3.4.2 设备树绑定


```dts

backlight: my-backlight {

    compatible = "my,pwm-backlight";

    pwms = <&pwm0 0 1000000 0>;    /* PWM 通道、周期 1ms */

    brightness-levels = <0 25 50 75 100>;

    default-brightness = <75>;

};

```

#### 3.4.3 sysfs 接口


```bash

# 读取当前亮度

cat /sys/class/backlight/my-backlight/brightness

  

# 设置亮度（0-100）

echo 50 > /sys/class/backlight/my-backlight/brightness

  

# 读取最大亮度

cat /sys/class/backlight/my-backlight/max_brightness

```

#### 3.4.4 源文件

```

drivers/my_backlight/

├── Kconfig

├── Makefile

└── my_pwm_backlight.c   # Platform 驱动实现

```

### 3.5 模块五：STM32 C8T6 从机固件

#### 3.5.1 功能

| 功能 | 说明 |

|------|------|

| 数据模拟上报 | 每 100ms 通过 UART 上报一帧 DATA_REPORT（温度按正弦曲线变化，模拟真实传感器） |

| 接收控制指令 | 收到 CTRL_CMD 后控制 LED 亮灭 |

| 心跳 | 每 1s 发送 HEARTBEAT 帧 |

#### 3.5.2 开发方式

- 裸机或基于 HAL 库

- 使用同一套帧协议（与 Linux 端 Line Discipline 对应）

- CRC16 算法与 Linux 端一致

## 七、简历项目描述（参考）

  

> **基于 RK3568 的超轻量实时 Linux 嵌入式系统** &emsp; 2026.03 - 2026.06

> - 使用 Buildroot 从零构建嵌入式 Linux 系统，深度裁剪 Linux 5.10 内核，**内核镜像从 15MB 裁至 5MB，根文件系统从 200MB 精简至 8MB**，采用 musl libc + BusyBox 达到极限精简

> - 逐项分析 800+ 内核配置选项，优化 initcall 启动链，实现**冷启动到应用显示 ≤ 5 秒**

> - 基于 TTY 子系统实现**自定义 UART Line Discipline 内核模块**，在内核态完成帧同步、CRC16 校验与状态机协议解析，与 STM32 从机实时通信

> - 手写 BME280 I2C 驱动并注册到 **IIO 子系统**，编写设备树实现传感器标准化数据采集

> - 实现 Procfs 内核调试接口，实时统计驱动收发帧数与 CRC 错误率

> - 项目开源于 GitHub，含完整内核裁剪分析记录与启动优化报告

## 八、风险与应对

| 风险 | 概率 | 影响 | 应对方案 |

|------|------|------|---------|

| 内核裁剪过度导致系统无法启动 | 高 | 中 | 每次只改 5-10 个选项，逐步裁剪，保留可回退的 defconfig |

| Qt EGLFS 在 RK3568 上无法使用 GPU 加速 | 中 | 低 | 降级为 LinuxFB 软渲染（界面简单，足够用） |

| Line Discipline 内核模块导致 panic | 中 | 中 | 先在 QEMU 上调试，再上真机 |

| BME280 I2C 通信不稳定 | 低 | 低 | 添加重试机制，检查上拉电阻 |

| 时间不够完成所有模块 | 中 | 高 | 按优先级砍：Qt 界面 > PWM 驱动 > I2C 驱动 > UART 驱动 > 内核裁剪 |
