## 场景假设

你的刺激频率是 **50Hz（周期 20ms）**，ADC 每隔 **10ms** 抛出一个快照。 假设在 **50ms** 的时间内，我们收到了 5 个快照，每个快照都会计算出一个 `peak_pos_uA`（正向峰值电流）。

但因为脉冲只发生在 20ms 周期中很短的一段时间里（比如只有 200us），所以不是每个 10ms 快照都能"抓到"脉冲的尖峰。有些快照恰好落在死区时间里，测到的峰值可能很小甚至接近 0。

假设 5 个快照测到的峰值是这样的：

| 快照编号 | 时间      | `peak_pos_uA` | 说明           |
| ---- | ------- | ------------- | ------------ |
| #1   | 0~10ms  | **19200**     | ✅ 抓到了一个脉冲的峰值 |
| #2   | 10~20ms | 800           | ❌ 落在了死区，只有底噪 |
| #3   | 20~30ms | **18500**     | ✅ 抓到了一个脉冲    |
| #4   | 30~40ms | **19000**     | ✅ 抓到了一个脉冲    |
| #5   | 40~50ms | 500           | ❌ 落在了死区      |

好了，我们来看两种方式怎么分别处理这组数据：

---

## 方案①：多脉冲峰值取平均

### 思路

不是把 5 个数全部平均，那样会被死区里的 800 和 500 拉低。 而是先**筛选**：只取那些"确实抓到了脉冲"的快照（比如峰值 > 某个阈值，如 `5000 uA`），然后对筛选出来的好数据做平均。

### 计算过程

有效样本 = { 19200, 18500, 19000 }   （#2 和 #5 被阈值过滤掉了）

有效样本数 = 3

平均峰值 = (19200 + 18500 + 19000) / 3 = 18900 uA

### 代码实现


```c

#define PEAK_HOLD_SLOTS    5       /* 最多缓存 5 个快照的峰值 */

#define PEAK_VALID_THRESH  5000    /* 低于此值认为是死区噪声 */
static uint16_t s_peak_ring[PEAK_HOLD_SLOTS];  /* 环形缓冲区 */
static uint8_t  s_peak_idx = 0;
/* 每 10ms ADC 回调时调用 */
void on_new_snapshot(uint16_t peak_uA)
{
    s_peak_ring[s_peak_idx] = peak_uA;
    s_peak_idx = (s_peak_idx + 1) % PEAK_HOLD_SLOTS;
}
/* 每 50ms 控制周期调用：取有效峰值的平均 */
uint16_t get_avg_valid_peak(void)
{
    uint32_t sum = 0;
    uint8_t  count = 0;
    for (int i = 0; i < PEAK_HOLD_SLOTS; i++)

    {
        if (s_peak_ring[i] > PEAK_VALID_THRESH)
        {
            sum += s_peak_ring[i];
            count++;
        }
    }
    if (count == 0) return 0;  /* 全是死区，说明可能没在刺激 */
    return (uint16_t)(sum / count);
}
```
### 优点

- **精确**：你得到了这段时间内"每一个真正脉冲的峰值"的数学平均值。
- **抗噪声**：一个偶然的毛刺（比如某次测到 25000），会被其他正常值"稀释"掉。

### 缺点

- **需要额外的数组**用来存储历史峰值（这里是 5 个 `uint16_t`，其实很小）。
- **阈值依赖**：你需要选一个合理的 `PEAK_VALID_THRESH` 来区分"有效脉冲"和"死区噪声"。这个值选不好，要么过滤掉了真数据、要么过滤不掉噪声。

---

## 方案③：一阶 IIR 滑动平均滤波

### 思路

完全不用数组，只需要**一个变量**。 每来一个新的峰值，不是替换掉旧值，而是让新值和旧的"历史结论"**按比例混合**：


其中 $\alpha$ 是一个 0~1 之间的"新值信任度"：

- $\alpha$ 越大（比如 0.5），滤波器对新值越敏感，跟踪快但抗噪差。
- $\alpha$ 越小（比如 0.1），滤波器越"迟钝"，变化缓慢但极其平滑。

### 计算过程（取 $\alpha = 0.3$）

初始 `filtered = 0`

| 步骤  | 新值    | 计算                       | filtered 结果        |
| --- | ----- | ------------------------ | ------------------ |
| #1  | 19200 | 0 × 0.7 + 19200 × 0.3    | **5760**           |
| #2  | 800   | 5760 × 0.7 + 800 × 0.3   | **4272** ← 被死区拉低了！ |
| #3  | 18500 | 4272 × 0.7 + 18500 × 0.3 | **8540**           |
| #4  | 19000 | 8540 × 0.7 + 19000 × 0.3 | **11678**          |
| #5  | 500   | 11678 × 0.7 + 500 × 0.3  | **8325** ← 又被拉低了！  |

经过 5 次迭代，结果是 **8325**，而真实的平均峰值应该在 **18900** 附近。

你看到问题了吗？——**死区快照中的小值会严重拉低滤波输出**。因为 IIR 滤波器不区分"这是一个有效脉冲"还是"这是一段空闲的死区"，它对所有输入一视同仁。

### 代码实现

```c
static int32_t s_filtered_peak_uA = 0;

/* 每 10ms 回调 */

void on_new_snapshot(int32_t new_peak_uA)

{
    /* α=0.3, 用整数运算: filtered = filtered*7/10 + new*3/10 */

    s_filtered_peak_uA = (s_filtered_peak_uA * 7 + new_peak_uA * 3) / 10;

}
```
### 优点

- **极其简单**：只需要 1 个变量，不需要数组。
- **无需设置阈值**：不用你去猜"多少算有效脉冲"。

### 缺点（在你的场景中很致命）

- **对间歇性信号不友好**：电刺激波形有大量"静默期（死区）"，这些 0 值会被当成正常数据吃进去，严重拉低滤波结果。
- **结果不代表真正的峰值**：你最终得到的不是"峰值电流"，而是一个"峰值 × 占空比"的混合值，在物理意义上已经不够精确了。

---

## 总结对比

|维度|① 峰值取平均（带阈值过滤）|③ 一阶 IIR 滑动滤波|
|---|---|---|
|实现复杂度|稍复杂（需要小数组+阈值）|极简（1 个变量）|
|抗噪能力|✅ 好（过滤死区噪声）|❌ 差（死区会拉低结果）|
|物理意义|✅ 代表真正的脉冲峰值均值|❌ 混合了死区和脉冲|
|适合场景|**间歇性脉冲**（你的场景）|连续信号（如温度、直流电流）|
